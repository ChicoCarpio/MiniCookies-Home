Cómo formatear y validar un JSON (y arreglar los errores típicos)

Una API te responde con todo en una sola línea, o un archivo de configuración no carga y el programa solo dice que hay un error de sintaxis en algún lugar. Leer un JSON así a ojo no sirve. Con Formatear y validar JSON lo ordenás en un clic, y el analizador te señala el lugar donde se rompió.

Formatear o validar, paso a paso

  1. Pegá el JSON en la caja de arriba.
  2. Tocá «Formatear (indentado)» para verlo con sangría de 2 espacios, o «Minificar» para dejarlo en una sola línea, sin espacios ni saltos.
  3. Si es válido, aparece «JSON válido» y el resultado se muestra en la caja de abajo. Si no lo es, aparece el motivo del error.
  4. Para llevarlo a otro lado, usá «Copiar resultado» o «Descargar .json». El archivo se llama json-formateado, seguido de la fecha y la hora.

Qué hace y qué no hace

La sangría es siempre de 2 espacios, y no hay opción para cambiarla. El orden de las claves se conserva: lo único que cambia es el espaciado. La herramienta no arregla nada. Valida y te señala el problema, y la corrección la hacés vos en la caja de entrada. Solo acepta JSON estándar, así que los comentarios y las comillas simples se reportan como error, aunque algunos programas los toleren.

La caja de abajo no se actualiza sola. Si cambiás el texto de la caja de entrada después de formatear, sigue mostrando la versión anterior hasta que tocás un botón de formato. Pero «Copiar resultado» y «Descargar .json» no usan esa versión: vuelven a formatear el texto actual con el último modo que usaste, indentado o minificado. Si el texto ya no es JSON válido, muestran otra vez el error y no copian ni descargan nada.

Lo que el formateador cambia sin que lo notes, porque aplica las reglas de JavaScript al volver a escribir el JSON:

  • Los enteros mayores que 9.007.199.254.740.991 pierden cifras al final: 12345678901234567890 vuelve como 12345678901234567000. Si el número es un identificador, conviene guardarlo como texto, entre comillas, si la aplicación lo acepta.
  • Los números se escriben en su forma más corta: 1.0 sale como 1, y 1e3 sale como 1000.
  • Los escapes como é se convierten en la letra: sale é.
  • Si una clave aparece dos veces en el mismo objeto, queda solo el último valor.

Cómo se ve un error

Si el JSON no es válido, la caja de entrada se pone roja y debajo aparece el motivo. Cuando el navegador informa en qué posición falló, la herramienta agrega la línea y la columna, con el texto «marcado arriba, en el cuadro de texto», y deja seleccionado el carácter problemático en la caja de entrada. Corregís ahí y volvés a tocar el botón.

El texto del motivo lo escribe el navegador, no Mini Cookies, así que puede venir en inglés y cambia de un navegador a otro. El carácter que se marca es donde el analizador notó el problema, y eso puede quedar un poco después del error real. Si lo marcado parece correcto, mirá justo antes.

Los errores más comunes

Estos cuatro son los que más aparecen cuando se escribe o se copia un JSON a mano.

Una coma de más al final

Es el número uno, sobre todo cuando copiás una lista, borrás su último elemento y dejás la coma.

{
  "name": "Ana",
  "age": 30,
}

JSON no admite una coma después del último elemento de un objeto o de una lista. El error suele señalar la llave de cierre, no la coma: con una versión reciente de Chrome o Edge, el mensaje dice algo como «Expected double-quoted property name in JSON at position 32 (line 4 column 1)». Basta con borrar la coma sobrante.

Comillas simples en lugar de dobles

JavaScript y Python aceptan comillas simples para el texto. JSON no: {'name': 'Ana'} falla, y el texto y las claves van entre comillas dobles, como en {"name": "Ana"}.

Claves sin comillas

Es lo que queda al copiar un objeto desde código JavaScript. {name: "Ana"} falla, porque en JSON las claves también son texto y van entre comillas dobles.

Comentarios

JSON no tiene comentarios, ni // ni /* */. Aparecen en archivos de configuración de algunos editores y herramientas, que usan variantes más permisivas.

{
  // usuario principal
  "name": "Ana"
}

El validador los rechaza, así que hay que borrarlos. Si necesitás dejar una nota, guardala en una clave propia, como "nota": "usuario principal", siempre que el programa que lee el archivo la acepte.

Otros errores frecuentes

  • Falta una coma entre dos elementos. El error aparece en el elemento que sigue.
  • Una llave o un corchete sin cerrar, o cerrado con el signo que no corresponde. Contá las aperturas y los cierres.
  • Valores que JSON no tiene: undefined y NaN no existen, y True o False con mayúscula tampoco. Solo valen true, false y null, en minúscula.
  • Comillas dentro de un texto sin escapar, como "dijo "hola"". Dentro de un texto, la comilla se escribe \".
  • Números con ceros a la izquierda, como 007.

Preguntas frecuentes

¿Cómo comparo dos versiones de un JSON? Formateá las dos con «Formatear (indentado)» y pegalas en Comparar dos textos. Así los cambios caen en sus propias líneas, y el comparador marca lo agregado en verde y lo quitado en rojo.

¿Cómo meto una imagen dentro de un JSON? Convertila con Convertir imagen a Base64: te devuelve el texto de la imagen con el prefijo data:, listo para pegar como valor entre comillas. Es un texto largo, así que conviene usar imágenes chicas.

¿Por qué el mensaje de error está en inglés? Porque lo genera el navegador al leer el texto. La línea y la columna sí aparecen en el idioma de la página.

Resumen

Para ordenar un JSON, pegalo y tocá «Formatear (indentado)»; para compactarlo, «Minificar». Si falla, mirá el carácter marcado o el anterior y buscá los errores de siempre: coma sobrante, comillas simples, claves sin comillas y comentarios. Si el JSON tiene números muy grandes, revisalos después de formatear, porque el formateador los cambia.
